dsh  deepseek-harness  cordis  plugin-market  plugin-manager

不托管插件，不给自己刷推荐，不把「没读到」说成「没有问题」。

## 它解决什么问题

DSH 生态已有数千个社区插件，但没有一个地方能回答三个最实际的问题：

1. **这个插件靠谱吗？** 星标只说明有人看见过，不说明它能用。
2. **我要装的东西从哪来？** 包名和仓库地址往往是两回事。
3. **装坏了怎么办？** 装完才发现不兼容，卸载还得手改配置。

这个插件把这三件事放进一个窗口：**目录 + 独立测评 + 可回滚的安装**。

## 功能

### 一屏看完 6000+ 插件

三个来源，一个窗口：

| 标签页 | 内容 |
|---|---|
| 精选目录 | 6000+ 社区插件，带分类、简介、作者、星标、下载量，以及 `dsh-trust-check` 扫出的能力清单与安全红线 |
| GitHub 搜索 | 目录之外的仓库，明确标注「未扫描」 |
| 已安装 | 当前 profile 的 bundle，按实际运行状态分组，可启停、更新、删除 |

分类筛选、按星标/下载/名称/更新时间排序、分页浏览，都在一个列表里完成。

### 安装前就能看到独立测评

整合 [DSH Plugin Review](https://review.lingshulab.com) 的判定。每个插件显示**一个判定 + 一个审计档位**：

| 判定 | 含义 |
|---|---|
| 真有用 | 装上之后确实把活干成了 |
| 帮倒忙 | 装上之后更差 |
| 没啥差别 | 测试范围内看不出差异 |
| 还说不准 | 数据不够 |
| 没法测 | 环境不支持或任务不适用 |

档位分「作者自测 / 体验快测 / 标准测评 / 深度审计」四档；报告标题里没写档位的，显示「未标注」而不是硬猜。

### 被判「帮倒忙」会拦一下

一个红色标签出现在列表里，通常是滞后于决策的——用户已经决定要装了才看见。所以确认栏会**展开那篇报告**，列出测评者、时间和链接，并要求勾选「我已阅读」之后才解锁安装按钮。

**它不阻止安装**，最终决定权仍在用户手里；它只保证你看过。

### 装之前知道它从哪来

详情抽屉里有一张「来源溯源」表：

| 项 | 说明 |
|---|---|
| 安装来源 | 实际交给 pnpm 的 spec —— 最关键的一行 |
| 仓库地址 / 发布者 | 可点击 |
| 分发渠道 | npm 注册表还是 Git 仓库（两者更新语义完全不同） |
| 仓库更新 / 测评资料更新 | 报告是否早于当前代码 |
| 星标数据时间 / 下载量时间 | 目录数据有多新 |
| 收录方式 | 精选目录收录，还是 GitHub 搜索发现（未收录） |

### 安装有进度，失败说人话

安装不是「转圈等结果」：

- 分段进度条：准备 → 检查 → 下载安装 → 应用 → 完成
- 实时滚动包管理器输出
- 已用秒数，可随时取消
- 失败时把错误码翻成一句话加下一步，原始输出折在「显示详情」后面

### 其它

- **版本历史**：抽屉里列出最新版本和最多 30 个历史版本，标出已安装的那一版，可装指定版本
- **截图画廊**：有截图的插件在抽屉顶部显示
- **向作者提问**：直接跳到 GitHub Issue 或 Discussions，只在仓库确实启用时显示
- **收藏与备注**：本地保存，不上传
- **中 / EN**：目录简介来自作者的中英文原文，不是机翻

## 安装

### 从 GitHub 安装（推荐）

```bash
dsh plugin add github:zjust7/dsh-plugin-market
```

装好后侧边栏「设置」旁会出现**市场**按钮。

> 本包**未发布到 npm**（`private: true`），所以 `dsh plugin add dsh-plugin-market`
> 这种按包名的写法装不上，必须带上 `github:` 前缀。

### 从本地源码

```bash
dsh plugin add /path/to/dsh-plugin-market
```

### 用 AI 安装

把下面这段连同仓库地址交给 agent：

```text
请在这个 DSH profile 里安装插件市场：
1. 运行 `dsh plugin list` 确认当前 profile
2. 运行 `dsh plugin add github:zjust7/dsh-plugin-market`
3. 确认输出里显示已启用（enabled）
4. 重启 DSH，在侧边栏找到「市场」按钮
失败时保留完整输出再报告，不要静默重试或换命令。
```

## 使用

1. 点侧边栏**市场**打开（点 ✕、按 Esc 或点窗外关闭）
2. 在**精选目录**里搜插件名、简介或能力
3. 点任意一行 → 右侧详情抽屉
4. 确认来源、测评、版本后点**安装** → 确认栏 → 完成

安装需要构建脚本时不会静默放行，会多出一个「允许这些脚本并重试」。

## 安装的包落在哪

市场安装的包走 profile 自己的包管理器，落在：

```
<profile>/node_modules/<包名>/
```

同时登记进该 profile 的 `package.json` 与 `dsh.profile.bundles`。不是落在本仓库目录。

## 配置

全部可选，缺省值见 `cordis.patch.yml`：

| 字段 | 默认值 | 含义 |
|---|---|---|
| `catalogTimeoutMs` | `45000` | 构建目录时每个请求的超时（2000–180000 毫秒） |
| `searchTimeoutMs` | `15000` | GitHub / npm 单次请求的超时（2000–180000 毫秒） |
| `reviewSnapshotUrl` | 内置地址 | 测评快照地址，可指向自己的镜像 |

## 安全边界

- **没有给模型注册任何工具。** 安装只能由人在窗口里点出来，模型自己装不了东西。
- 窗口与 Host 走 `ctx.connection.fetch` 的精确路由，与 `/api` 共用浏览器会话校验；本机其它程序拿到地址也调不动。
- 安装交给 profile 自己的 `pluginManager`，失败、取消或装入无 bundle 的包都会还原 `package.json` 与锁文件。
- 需要构建脚本的包不被静默放行，必须再点一次授权。
- 只读第三方公开数据，不写、不提交、不需要对方账号。

## 数据来源与新鲜度

| 数据 | 来源 | 更新方式 |
|---|---|---|
| 插件目录 | `awesome-dsh-plugin.com/plugins.json` | 上游每天重建 |
| 实时星标 | `api.github.com` 批量搜索 | 每页可见行刷新一次，缓存 10 分钟 |
| 版本历史 | npm registry / GitHub Release | 按需拉取，缓存 30 分钟 |
| 测评判定 | 公开快照文件 | 每天一份，随包附带一份兜底 |

**三条诚实规则**，实现和测试都会验证：

1. 读不到就是 `null`，窗口显示 `—`，**不用 `0` 冒充**
2. 报告标题没写档位就显示「未标注」，**不猜**
3. 安全结论只认「深度审计 / 安全面快测」档位，**不把能力判定当安全背书**

## 开发

```bash
node smoke-host.mjs     # 快速冒烟
node verify-host.mjs    # 完整契约测试（需要网络）

DSH_MARKET_OFFLINE=1 node verify-host.mjs   # 跳过联网段落
```

Host 半边是 `index.js`，浏览器半边是 `client.js`（无构建步骤，走 `window.__ModuleLoader__`）。
两者之间的接口写在 [`docs/API.md`](docs/API.md)。
